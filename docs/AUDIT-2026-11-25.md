## Bug 與技術債

1. 遠端官方 E2E 已失敗但進度文件仍寫未執行。index_semantic 每批最多 24 段，embed 使用預設 90 秒 transport timeout；CPU runner 日誌已證實逾時。下一步應量測批量、冷啟動與上限，保留可續跑能力。
2. 輸入描述限 160 字，來源在 services/api/queries.py:29、patents.py:134，與長篇構想需求有落差。
3. evidence.select_excerpt 逐字命中且每特徵只選一片段，沒有同義表述的多段語義證據召回。可證明引文存在，尚無法證明判定完整。
4. 預覽翻頁會重新跑檢索／模型，無語料快照。保存結果已有排名快照，但不能重建當時全部索引。
5. 詞彙基線是 han-bigram + PostgreSQL ts_rank，沒有 BM25；向量是精確掃描，沒有 ANN。小資料量可運作，大量效能未驗證。
6. 舊 API 冒煙腳本與新種子涵蓋的期別不同，尚無一致的測試語料契約。
7. HANDOFF 指向的暫存原始物件目錄及工作區 .patent-data 在本次檢查沒有檔案，原始物件需長期保存及備份。這不等於已證明其他位置也無副本。
8. README 首段仍寫沒有索引語料，與實際程式、資料庫和後文不符。主表 M0–M4 DONE 也未涵蓋全部擴充產品規格。
9. migration 多項刻意拒絕降版，但尚無實測備份復原。Starlette TestClient 有既有棄用警告。

## 資安風險及改善方向

| ID／嚴重度 | 證據、影響與建議 |
| --- | --- |
| S1 高，網路設定條件成立時 | docker ps 顯示 ollama_server 綁定 0.0.0.0:11434 與 IPv6。本機 /api/tags 不帶認證可讀。若防火牆允許不可信來源，可直接耗用模型資源。應改綁回環或隔離容器網路，必要時加受控代理。沒有測試外部網路可達性。 |
| S2 高，正式環境 | Compose 的 API 與遷移共用 POSTGRES_USER。實測 current_user=patentscope、usesuper=true。應把 migration owner 與 API 最小權限角色分開，避免單一 API 漏洞影響整個 DB。 |
| S3 高，公開服務 | services/api/queries.py、comparisons.py、patents.py 的模型端點未要求登入或一般限流；註冊會直接執行高成本 scrypt。可被大量請求耗用 CPU、GPU、記憶體與工作執行緒。需 IP／帳號配額、併發與佇列上限。 |
| S4 中 | identity.login_account 依 email hash 限流，有可預期的帳號暫時鎖定及併發計數競態。已知郵件可被第三人造成暫時無法登入；跨地址請求仍能繞過整體資源限制。需要多層節流與原子計數。 |
| S5 中，待對外部署 | Nginx 具有 nosniff 和 no-referrer，但未看到 CSP／frame-ancestors 或外部 TLS 配置。開發回環 HTTP 是現有運作模式；正式入口的傳輸及點擊劫持保護尚待設計與實測。 |
| S6 中 | 除 readiness 外缺結構化操作稽核、保留期限、備份／復原證據。現有來源原始物件依賴暫存目錄，影響可追溯性及災難復原。 |

已看到的保護包括隨機鹽 scrypt、雜湊 token、24 小時效期、登出撤銷、參數化 SQL、所有權查詢與複合外鍵、XML 大小及 DOCTYPE 限制、模型位址白名單和 digest 核對、React 文字輸出。當次 Git 常見私鑰及 token 模式掃描未命中；這不是完整秘密掃描或滲透測試。

## 下一階段與兩週 MVP

第 1–3 天先修官方 CI 的 CPU embedding 逾時，統一測試語料契約並更新實際狀態。第 4–6 天建立持久原始物件目錄與備份復原，處理模型網路曝露、DB 最小權限及高成本端點配額。第 7–10 天由人員複核現有 35 組候選，再重跑詞彙、向量與 hybrid+rerank 的 P@10、R@10、nDCG、MRR 和延遲。第 11–14 天修正主要回歸、統一操作文件並完成一次乾淨部署驗收。

兩週交付範圍應定為受控本機／內網試用版，固定官方樣本覆蓋、可編輯短篇構想、混合檢索、來源詳情、逐字引文、專案保存及繁中 PDF。若要把非同步任務與長篇描述也列入這兩週，需縮減其他工作並再依現有程式估工。人工標註需要使用者或指定人員參與，不能用 LLM 自評補作完成。
