# 架構決策

## M4 文件篩選

- 詞彙、向量與混合檢索使用同一段參數化 SQL 篩選，先於候選分支的排序截斷。使用官方文件版本的公開／公告日期與申請人欄位，指定日期時排除未知值。保存搜尋以既有請求欄位保留條件，舊紀錄預設無條件。

## M4 跨文件比對矩陣

- 以同一次搜尋的技術特徵為列、已完成比對的文件版本為欄。預覽使用頁面記憶體，保存的搜尋從既有 API 回讀各版本的判定及引文。公開與公告按各自的文件 UUID 顯示。

## M4 研究專案刪除

- 只允許刪除空白專案，由 PostgreSQL 外鍵拒絕仍有搜尋、收藏或 Session 的刪除。API 將外鍵衝突回報為 409，畫面提供明確的二次確認。

## M4 AI Session

- Session 透過研究專案繼承帳號權限。每次分析成功後，以同一交易保存使用者構想與本機模型回應，並保留模型名稱、權重摘要及分析流程版本。模型出錯時該輪不寫入。
- Session 提供可回顧、可帶入檢索表單的技術草稿。各輪目前獨立拆解，跨輪上下文與搜尋證據仍分別由後續對話功能與已保存搜尋處理。

## M4 專案收藏

- 以專案 UUID 與官方文件版本 UUID 為複合主鍵。公開與公告可分開收藏。同一版本在不同專案可有不同筆記。重複收藏保留原筆記。
- 筆記由收藏持有，單獨更新。移除收藏會移除該筆筆記，搜尋快照與比對證據維持各自的生命週期。

## M4 研究專案歸檔

- 每個搜尋紀錄可連到一個同帳號的專案。使用可空的 `project_id` 保留舊紀錄，並以 PostgreSQL 複合外鍵限制 `(user_id, project_id)`。移動或解除歸檔只更新關聯，保留當次候選與引文。

## M4 私人搜尋歷史

- 訪客預覽與「搜尋並保存」使用不同操作。保存時直接執行已驗證的搜尋端點，後續分頁讀取該次候選快照。瀏覽保存的文件時，從同一紀錄還原已保存比對。
- Bearer 憑證及畫面上的私人資料只保留於頁面記憶體。登出或收到已驗證端點的 401 時清空，重新整理需再登入。伺服器仍依原 24 小時效期判斷 token，立即撤銷留待後續。

## M4 瀏覽器檢索預覽

- 前端沿用同源 API 代理。編輯中的構想與特徵存於頁面記憶體。比對使用最近一次成功檢索送出的特徵與選定的文件版本 UUID，避免編輯中的草稿改變既有結果的解讀。
- 初版採同步預覽 API，提供等待及錯誤回饋。歷史讀取會串接已保存的搜尋紀錄，以固定順位回顧候選與證據。

## M3 候選重排

- 呼叫端明確啟用時，使用本機分析模型以標題與摘要重排融合後前 8 筆。伺服器要求完整的候選排列，拒絕重複、遺漏或新增候選。結果保留原融合排名與分數，排序觀察不作為品質提升的證明。

| 決策 | 階段 | 理由與適用範圍 |
| --- | --- | --- |
| React、TypeScript、Vite 與 Tailwind CSS | M0 | 遵循 AGENTS.md §2。本機狀態頁透過同源代理讀取 API，前端不需要跨來源設定。 |
| PostgreSQL 16、pgvector 與 Alembic | M0 | 以一個資料庫同時支援後續關聯資料與向量檢索。第一個遷移只安裝向量擴充功能，避免在取得官方樣本前假設識別碼或資料欄位。 |
| 分開探測 API 存活與資料庫就緒 | M0 | 存活檢查獨立於 DB。就緒檢查執行實際的向量距離查詢，可辨識連線失敗或擴充功能缺失。 |
| Compose 先遷移再啟動 API | M0 | DB 健康後由一次性服務執行遷移，成功才啟動 API。開發堆疊的 Web、API 僅暴露於本機，DB 使用內部網路。 |

TIPO 資料格式與版本鍵、斷詞策略、嵌入模型與部署環境待後續里程碑驗證。架構變更依 AGENTS.md 走 ADR 與審核。

## M1 資料來源與版本

- 官方卷期索引與個案說明書分開保存。以 SHA-256 定位原始位元組，由批次與來源定位連回檔案。DEMO 資料使用獨立的來源鍵及管轄值。
- 文件版本用公開號、文件階段、來源內容雜湊與解析器版本識別；kind code 保留給來源明確提供時。只有書目和含全文的資料版本可並存，查詢層須依研究範圍選擇可用版本。
- XML 原文以 XPath 和檔案雜湊定位。說明書的日期欄位與書目 API 的申請日語義不同，索引缺少的日期留空。
- 從官方 FTPS 清單核對卷期、公開號及申請號後，依序下載個案並記錄 URL。每次成功傳輸進快取，重跑只向官方要求未成功的個案。容器可只讀取主機已驗證的下載快取。
- 公告索引以證書號與申請號交叉核對。公告和公開各自保存原始來源與請求項；缺少明確請求項編號的公開全文保留原檔並隔離，不以段落順序補寫編號。
- 匯入可記錄官方索引 URL。歷史公開卷期的 FTPS 路徑須與匯入期別相符，最新公開及公告索引僅接受各自的官方網址，索引內容仍須通過期別驗證。

## M2 精確號碼查詢

- 呼叫端明確指定申請、公開或公告號，避免數字格式相同時誤判。精確查詢回傳可取得的版本，後續以版本 UUID 讀取原文。只有臺灣且有成功或部分成功的正式來源紀錄會顯示。
- 在隔離語料的 143 個文件版本執行 `EXPLAIN (ANALYZE, BUFFERS)`。申請號使用文件申請案索引，公開號使用文件號索引，公告號使用文件唯一鍵索引。小型申請案表使用循序掃描。單次 SQL 執行分別為 0.365、0.246、0.140 ms，為本機暖快取觀察值。

## M2 詞彙基線

- 使用 `han-bigram-v1`，對連續漢字取相鄰雙字，英數保留連續詞，統一字寬與大小寫。PostgreSQL `simple` 接收已切好的詞，以 `ts_rank` 排序並對標題和摘要加權。此基線沒有 BM25、同義詞、簡繁轉換或跨片段語意比對。 [PostgreSQL 16 全文搜尋索引文件](https://www.postgresql.org/docs/16/textsearch-indexes.html)
- 已匯入文件以版本 UUID 與分詞器版本追蹤索引。索引程式與標記在同一交易寫入，原文表仍供證據定位。新匯入資料須執行索引程式。
- 143 個真實文件版本共 1,654 個文字片段。四個已知目標的中英文案例均在第 1 名命中，屬冒煙驗收，相關性評估留待後續。一次 `EXPLAIN (ANALYZE, BUFFERS)` 的英文加 IPC 查詢使用 `ix_patent_lexical_terms`，執行 0.555 ms，分類表採循序掃描。

## M2 語意基線

- 重用環境已安裝的多語 Qwen3-Embedding-0.6B。Ollama adapter 以設定切換本機模型，版本由模型名稱、SHA-256 與處理流程識別。每次嵌入前後驗證 digest，維度為 1,024。本機請求停用代理及重新導向。 [Qwen 模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B) · [Ollama 嵌入 API](https://docs.ollama.com/api/embed)
- 對標題、摘要、請求項和段落分別嵌入。長文字以 1,000 字元窗口與 100 字元重疊分段，記錄原文起訖。索引與查詢必須使用同一組模型識別，更新只處理該模型尚未索引的文件。
- 驗收使用 pgvector 精確餘弦距離，先依語料與 IPC 過濾，再以每份文件最相近的片段計分。B01J 英文改寫案例的查詢計畫使用向量表的複合主鍵定位候選片段，SQL 執行 1.316 ms，未含模型推論。大語料上的 ANN 與整體相關性留待實測。 [pgvector 文件](https://github.com/pgvector/pgvector)

## M3 混合候選

- 採 Reciprocal Rank Fusion，`k=60`。以版本 UUID 彙總各分支的 `1/(k+rank)`，同一版本的單一分支只計第一次。保留原分數供查核。 [RRF 原論文](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)
- 先融合再去重，避免同一公開文件的書目版與全文版互借分數。以 RRF、內容涵蓋範圍、UUID 排序後，同一文件階段、文件號與 kind code 保留第一筆。分支各取最多 100 筆，採同一 PostgreSQL 讀取快照。

## M3 技術特徵與查詢展開

- 本機分析使用 Ollama JSON 模式，提示提供格式範例並以 Pydantic 驗證，伺服器配置特徵 ID。Ollama 0.13.5 實測在將此 schema 轉換為 grammar 時崩潰，因此改用 JSON 模式。沿用本機連線、停用代理及重新導向、請求前後 digest 核對。模型輸出為待確認草稿。 [Ollama 結構化輸出](https://docs.ollama.com/capabilities/structured-outputs)
- 展開保留原始查詢，使用者編輯後的特徵描述與中英文詞才會加入檢索。詞彙分支以受控的分詞結果組成布林式，向量分支將詞及描述附到原始查詢。IPC 候選不會自動套用。
## M3 技術比對預覽

- 以指定版本的正式原文和來源關聯為邊界。每項特徵最多選一段字詞命中的片段供本機模型判定，伺服器依原文索引擷取引文。缺乏片段時不送模型，依有無可查正文回傳未找到或不確定。此方法的證據召回受字詞命中與單片段限制。
## M3 私人搜尋紀錄

- 由獨立的已驗證端點保存搜尋，使用者可以先預覽。以單一交易寫入請求、排名設定及有上限的完整候選集合，保留各文件版本的順位與分數。
- 使用帳號 UUID 限定每次私人讀取。密碼採獨立隨機鹽與 scrypt，Bearer token 只存 SHA-256 摘要並於 24 小時失效。此為本機開發階段的驗證流程。 [OWASP 密碼儲存指引](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
- 比對結果依搜尋紀錄及文件版本保存，重送讀取第一次寫入的結果。保存的候選與引文可供回顧，完整語料版本化及重跑仍待實作。
